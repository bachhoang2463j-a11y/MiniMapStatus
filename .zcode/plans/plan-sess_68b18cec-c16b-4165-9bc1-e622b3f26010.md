# 状态栏数据结构弹性化重构方案

## 一、确认的现状问题（均已核实到代码行）

1. **载具丢失有两层根因**：
   - `mmsNormalizeState`（`MiniMapStatus.html:9082-9092`）：旧格式「用户列表」中所有 base 类条目（据点、载具）被 `Object.assign` 合并进同一个 `据点` 对象，载具在归一化阶段即被摧毁（其 名称/武器/弹药/杂物 会覆盖据点同名字段）。
   - `roster.base` 单槽位设计：导入只取 `moduleNames[0]`（`11446`），合并只处理一个 `baseModuleName`（`9742-9763`），且 `MMS_KNOWN_MODULES`（`8906`）把 `据点` 锁为已知模块——据点/载具同存必丢一个。
2. **初始武器/初始物品确认是校验字段**：与 `属性` 一起走命令协议（`mmsApplyAttrCommands`/`mmsApplyItemCommands`），初值即命令基线；无独立的初始值比对。自由字段（穿着/内心）每轮全量输出、不校验。
3. **弹药/消耗/道具被主动过滤**：导入时 `11409` 行 `/弹药|消耗|道具/ → continue`，无法配成独立校验字段。
4. **提示词写死**：`mmsBuildSystemPrompt` 中 `['穿着','内心']` 回退（`9808`，另有 5 处同类回退）、`属性/武器/物品` 硬编码（`9828-9830`）、静态 `MMS_JSON_SCHEMA`（`8841`）写死角色与据点字段。

## 二、新数据模型（聊天变量 `$mms_roster`）

```js
{
  characters: [{
    name, portraitTag, avatar, role,
    attrs: [{key, value}],        // 属性（数值校验）保留现状，可为空
    fields: [                     // ★ 统一字段列表，完全自定义，顺序即输出顺序
      { key: '武器', initial: '[🔪] [萨维奇M1907…]', mode: 'check' },  // check=命令协议校验
      { key: '物品', initial: '…',                mode: 'check' },
      { key: '弹药', initial: '[🔩] [.32子弹：30]', mode: 'check' },
      { key: '道具', initial: '[⚗️] …',           mode: 'check' },
      { key: '消耗', initial: '[🧪] …',           mode: 'check' },
      { key: '穿着', initial: '',                 mode: 'free' },     // free=每轮全量输出
      { key: '内心', initial: '',                 mode: 'free' },
    ],
    personaPrompt: ''
  }],
  modules: [                      // ★ 多固定模块数组，据点/载具共存
    { enabled: true, name: '据点', titleVal: '澳大利亚酒店总督套房', cash: '4767.20美元', fields: [{key:'武器',value:'…'},…] },
    { enabled: true, name: '载具', titleVal: '特制凯迪拉克防弹轿车', cash: '', fields: […] }
  ],
  // maps/mapTags/bigmapArt/absentText 等保持不变
}
```

- 武器/物品不再是必备字段，只是新建角色时的默认预填（武器/物品=check，穿着/内心=free，可删可改模式）。
- 模块内 `名称`（titleVal）/`现金`（cash）保留为标准键，cash 留空则该键不输出（你的载具只有名称没有现金，正合适）。模块清单字段全部走物品命令协议（与现状一致）。

## 三、代码改动（均在 `MiniMapStatus.html`）

### 1. 数据模型与迁移（`loadRoster` 10111-10165、`saveRoster` 10374）
- 归一化读取：`r.base` → `modules:[base]`；每个角色 `weapons/items` → check 字段、`freeFields/freeInitials` → free 字段，合成 `fields[]`。
- 保存时写回新结构，旧聊天首次保存后自动完成迁移，无需用户操作。

### 2. 归一化修复（`mmsNormalizeState` 9063-9118）
- base 类条目不再合并：每个 base 条目按 `plain` 名（据点/载具/任意）独立输出为顶层模块，`总览`→`名称/现金` 的提取逻辑保留并逐条目执行。

### 3. 合并引擎泛化
- `mmsTemplateChar`（9412）：遍历 `r.fields`，check 字段用 initial 作基线、free 字段同现状；attrs 为空则不输出 `属性` 键。
- `mmsMergeChar`（9562）：按 mode 分流——check 字段走 `mmsApplyItemCommands`，free 字段透传/保留；跳过清单 `['名字','属性','立绘', ...fieldKeys]` 动态生成。
- `mmsTemplateBase`/`mmsMergeState`（9549、9667）：遍历 `roster.modules`，逐模块做基线补齐 + 现金/清单命令合并；已知模块集合 = 内建（日期/地点/小地图/大地图/角色列表/人物/行动选项/用户列表）+ 名册模块名，其余顶层模块继续走自定义透传（不丢）。
- `MMS_KNOWN_MODULES`（8906）移除 `据点` 特判，改为函数按名册动态计算。
- `mmsExtractQuantPoints`（9468）遍历所有模块名。
- 「不在场」占位保留 `/内心/` 名字匹配启发式（含"内心"的字段写 absentText）。

### 4. 提示词与 JSON Schema 动态化
- `mmsBuildSystemPrompt`（9786）：
  - 角色示例行由名册字段并集生成，删除 `['穿着','内心']` 硬编码回退（9808 及 9420/11121/11419/12590/12922 共 6 处）。
  - 模块结构段循环 `roster.modules`，逐模块输出 JSON 骨架。
  - 「校验字段」段落改为：适用于角色列表与各固定模块中标注为校验的字段；`checkTargets` 动态拼装。
  - 固定成员规则文案（9891-9892「撰写其内心、穿着」）改为引用字段配置的通用表述。
- 新增 `mmsBuildJsonSchema(roster)` 按名册动态生成 response_format，替换静态 `MMS_JSON_SCHEMA`（8841，`generateRaw` 调用点 11162 同步替换）；schema 仅枚举已知可选字段，不限制 additionalProperties，避免误伤自定义模块。
- 用户消息 `<固定成员>` 段（11114-11127）：逐成员列出字段清单及校验/自由标注，LLM 据此区分命令输出与全量输出。

### 5. 导入重构（`autoImportRosterFromState` 11388-11469）
- **分类规则**：角色字段值被 `[…]` 包裹（`/\[[^\]]+\]/` 命中）→ 校验字段（带入初值）；无中括号 → 自由字段。删除 `/弹药|消耗|道具/` 过滤行（11409）。
- **多模块收集**：所有非内建、对象值的顶层模块（不限据点/载具）全部识别为候选固定模块。
- **勾选导入**：用自定义模态框（复用扩展现有面板样式）替代 `confirm()`，列出检测到的新角色与模块，逐项复选框，只导入勾选项。

### 6. UI 表单改造
- 角色编辑表单：删除「初始武器/初始物品」两个固定输入框和「自由属性」区块，合并为统一「字段」列表（每行：字段名 + 初始值 + 校验/自由切换，可增删排序）；新建角色预填 武器(check)/物品(check)/穿着(free)/内心(free)。
- 固定模块表单：由单模块改为模块列表（添加/删除/启用），每模块含 名称/标题值/现金/清单字段行；`renderBaseForm`（12118-12172）重写。
- `renderRosterList`、编辑回填（12911-12922）同步适配。

### 7. 渲染端
- `renderCharacterTabs`（8022-8043）的 `rootData['据点']` 硬编码分支泛化为遍历名册模块名，每模块一张卡片/标签页（标题用模块名）。

## 四、不改动范围

属性 attrs 数值模型、地图（小地图/大地图/绘图）、人物/行动选项内建模块、世界书注入（蚀心模式）、显示正则、存储分层（chat/message/global 变量）均维持现状。

## 五、实施顺序与验证

1. 数据模型+迁移 → 2. 归一化修复 → 3. 合并引擎 → 4. 提示词/Schema → 5. 导入 → 6. UI → 7. 渲染端。

验证方式：用你提供的这份 `<Status_block>` YAML 实测——
- 导入快照后：`据点` 与 `载具` 同时成为独立固定模块（名称/现金/清单字段各自正确）；
- 名册中埃利奥特等角色带 弹药/道具/消耗 校验字段（初值含中括号清单），索恩的 消耗、林有声无弹药等差异逐角色保留；
- 勾选导入弹窗可只选部分成员；
- `mmsBuildSystemPrompt` 输出的示例模板与字段说明完全来自名册配置，无任何写死的穿着/内心/武器/物品；
- 一轮更新后载具模块不消失、弹药数量按命令协议增减。

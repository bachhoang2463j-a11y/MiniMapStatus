# 状态栏我方数据 → 战斗前端传入（开局直连）

## 定位

状态栏（MMS stat_data）持有我方出战的**数值真相**（HP/MP/属性/物品数量），但**没有技能**。本特性让战斗开局时我方数值以状态栏为准——Combat_block YAML 仍提供技能骨架与角色名单，勾选后数值层被状态栏覆盖。这是"反向直连"的第一步（开局校准），与战后正向直连（`$rpg_combat_result`）构成闭环。

## 数据通路

```
Combat_block YAML（技能/角色名单/敌方）
  └─ applyPersistedRoster()（15563，现有）
       └─ 【新增】applyStatusBarRoster()：勾选时从 stat_data 读我方数值，同名覆盖 heroesData
            ├─ 属性：HP/MP/Armor（含 cur/max 解析）——直接覆盖
            ├─ Atk/Speed/职业：按用户现有"攻防速持久化"全局开关语义
            │    ├─ 未勾选持久化 → 优先 YAML 值，其次持久化值（现状逻辑），状态栏缺键不介入
            │    └─ 勾选持久化 → 直接持久化值（现状逻辑），状态栏缺键不介入
            │    （即：Atk/Speed/职业 仅在 YAML 与持久化都缺失时才回落默认 10/100——完全保持现状，状态栏不管这三项）
            └─ 物品：同名匹配（剥 emoji/备注后整词精确匹配 rpg_combat_roster 持久化物品），
                 命中 → 以状态栏数量覆盖该物品 count；未命中 → 不传入（保留 YAML/持久化值），控制台提示
```

## MMS 侧数据格式（读取方适配，零改动）

状态栏角色条目：`角色列表[].角色 = { 名字: '🔮埃利奥特', 属性: '[❤️HP:62/100][💠MP:5/60][🛡️Armor:5]', 物品: '[💼][绷带x3][.45子弹：0]' }`
- 属性串：剥 emoji 后按 `[键:值]` 解析；HP/MP 为 cur/max 型，Armor 为纯数值
- 物品串：`mmsParseItemList` 的三种数量形态（xN / ：N / ：N+后缀），带括号备注
- **MMS 零改动**——战斗侧适配读取（`getVariables({type:'message', message_id: <最新AI楼>}).stat_data`），需要的话 message_id 用「从最新楼往前找最近一份 stat_data」的回溯（照 MMS 侧 findPrevState 思路，最多 50 楼）

## RpgCombat 改动（index.html）

### 1. `#start-actions` 勾选框（1625 区域）

`「📋 状态栏传入」`checkbox（默认不勾=保持现状纯 YAML）+ 说明小字：勾选后我方 HP/法力/护甲与弹药消耗品数量以状态栏最新快照为准，技能仍来自本楼 Combat_block；未勾选则完全使用本楼 YAML 数据。位于「Yaml 载入」按钮旁，与 worldbook 下拉同级。

### 2. `applyStatusBarRoster()`（新增，15563 附近）

挂载点：`onCombatDataReceived`（8521）内 `applyPersistedRoster()` **之后**、`#start-actions` 显示之前读取并暂存状态栏快照（不立即覆盖——用户可能不勾）；真正的覆盖发生在 `startGame()`（12350）入口处按勾选状态执行。特性检测 + 整体 try/catch 绝不抛出（照 exportCombatResultToStatus 模式）：

```js
function readStatusBarSnapshot() → { heroes: [{name, hp, maxHp, mp, maxMp, armor, items: [{name, count}]}], source: message_id } | null
// getVariables({type:'message', message_id}) 从 getCurrentMessageId() 起往前回溯 ≤50 楼找 stat_data
// 剥名字 emoji（getCleanNameAndEmoji 复用）、解析属性/物品串（新写轻量解析：emoji 剥除 + [键:值] + 三种数量形态）

function applyStatusBarRoster(snapshot) → { applied, unmatched }
// 按名字整词匹配 heroesData（mmsNormalizeName 同款归一：剥 emoji/标点/小写）
// 覆盖 hp/maxHp/mp/maxMp/def(Armor)；物品按剥备注后的显示名与 hero.items 同名匹配（整词），命中覆盖 count
// Atk/Speed/职业：不介入（保持现有 YAML→持久化→默认 的链路）
// 返回报告供 UI 反馈（加载成功提示：N 名成员已按状态栏校准）
```

### 3. startGame 入口接线（12350）

```js
const statusBarChk = document.getElementById('start-statusbar-import');
if (statusBarChk && statusBarChk.checked && _statusBarSnapshot) {
  const report = applyStatusBarRoster(_statusBarSnapshot);
  showLog(`✅ 已按状态栏校准 ${report.applied} 名成员数值` + (report.unmatched.length ? `（未匹配：${...}）` : ''));
}
```

### 4. 边界

- 状态栏无数据（快照 null）：勾选也不生效，提示「未找到状态栏数据，使用 YAML 数值」
- 名字不匹配的角色：跳过并提示（YAML 值保留）
- 战后直连（`$rpg_combat_result`）与开局传入互不影响（一写一读，key 不同）
- 弹药 `：0`（已耗尽红条目）：照常传入 count=0——战斗侧绑定预筛会自然禁用对应技能，语义正确

## 验证（harness test16）

1. 状态栏快照读取：mock message 变量含 stat_data（带 emoji 属性串/物品串）→ `readStatusBarSnapshot` 正确解析（剥 emoji、cur/max、三种数量形态、备注剥离）
2. 回溯：本楼无 stat_data → 找到前面最近一楼
3. 勾选覆盖：勾选 + 点 startGame → heroesData 数值与状态栏一致；物品 count 覆盖（绷带 3→1、子弹 40→12）
4. 不勾选：数值保持 YAML 原值（现状回归）
5. 同名匹配：`【绷带】` vs `【高级绷带】` 不误伤；未匹配角色提示
6. Atk/Speed 不介入：状态栏无此键时 YAML 值保留
7. 快照缺失：勾选但无数据 → 提示 + YAML 值保留

## 明确不做

- 技能从状态栏传入（状态栏无技能数据，骨架必须来自 Combat_block/持久化）
- Atk/Speed/职业从状态栏传入（用户已确认：沿用现有攻防速持久化开关语义，状态栏不管这三项）
- 敌方数据传入（敌方仍由 Combat_block/世界书提供）
- 全局设置面板开关（用户已确认用开始界面勾选，每次开局可选）

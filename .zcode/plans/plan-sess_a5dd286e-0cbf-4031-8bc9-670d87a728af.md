## 二、固定角色名册

**存储**：聊天变量 `$mms_roster`（$前缀对AI宏不可见；随聊天导出）：
```js
[{ name:" 🛡️弗兰克", portraitTag:"", attrs:[{key:"❤️HP",value:"18/18"},{key:"🛡️Armor",value:"6"}],
   freeFields:["穿着","内心"], items:"[💼] [...]", weapons:"" }]
```
**设置UI**（设置面板新分组「固定角色」）：名册列表（名字+属性键摘要+删除按钮）、【添加角色】表单（姓名 / 立绘标签可选 / 校验属性行：键名可含emoji+初始值 / 自由属性键：默认穿着、内心 / 初始武器·物品可选）、两个占位文案设置（默认「本轮未提及」「在场·本轮未详」）。立绘仍走 PORTRAIT_MAP 名称匹配（现有机制）。

**渲染**：合并后固定角色自然存在于 `角色列表` → 现有「角色状态详情」标签页中常驻，**样式零改动**（按你明确的要求）。

**合并逻辑**（runUpdate 内，写入前）：
- AI输出含该角色（名称去emoji/空格匹配）→ 校验字段=命令应用结果，自由字段=AI值
- AI漏输出但有上次状态 → 校验字段保持上次值；**内心=名称命中本轮正文？"在场·本轮未详":"本轮未提及"**；穿着等其他自由字段保留上次值
- 刚添加无历史 → 校验字段=名册模板值，自由字段=占位
- 副作用：合并进状态 → 深度0注入带上全部固定角色 → **正文API不会再忘记他们**

## 三、校验字段命令协议

**语法**（AI输出，嵌入原字段位置）：
- 属性：`[键-N]`减少 / `[键+N]`增加 / `[键:值]`绝对值。例：`属性: "[HP-2][SAN:55]"`
- "18/18"格式只作用于当前值（上限保持，结果夹取[0,上限]）；无上限值（Armor:6）直接运算，下限0
- 物品清单：`[+物品名]`获得 / `[+物品名xN]`获得N个 / `[物品名-N]`消耗 / `[物品名:N]`设为；**数量归零自动移除**；名称模糊匹配（去emoji/空格，支持"(已损坏)M1911x2"这类备注内嵌计数）
- 现金：属性式命令 `[团队现金-12.80]`，解析存储串中的数字运算，保留货币后缀
- 新登场角色（当前状态没有的）：属性与清单输出**完整值**（带emoji键名全量串）；程序以"段键名含emoji"识别为全量替换
- 未提及的校验字段：AI不输出该字段 → 结构性保持不变

**程序应用引擎**：parseAttrCommands / parseItemCommands / applyCommands（纯函数，含夹取与警告日志）。

## 四、更新提示词重写

**系统提示词**（MMS_UPDATE_SYSTEM_PROMPT v2）：新模块结构说明 + 命令语法与示例 + 固定成员规则（剧情提及→输出条目；明确不在场→内心写"不在场"；完全未提及→可省略条目）+ 18场景白名单 + 坐标10~90 + 只输出JSON。

**用户消息**：`<当前状态>`YAML + `<固定成员>`名册名单（从 $mms_roster 生成）+ `<前情提要>` + `<最新剧情>` + 指令。

**在场规则只在全局提示词声明**（按你的要求，不做单独机制）。

# MiniMapStatus (故事情节与战术地图状态栏)

`MiniMapStatus` 是一个专为 **SillyTavern (酒馆)** 设计的高颜值、交互式状态栏与战术地图小部件，运行于 **酒馆助手 (TavernHelper / JS-Slash-Runner)** 的 iframe 渲染环境。

它通过独立 AI（与正文 API 分离）维护一份完整的跑团状态数据（角色属性、物品、小地图坐标、人物/据点、行动选项），渲染为包含**战术视觉地图**、**角色多维状态卡片**、**动态立绘**、**物品行囊**的交互式面板，并把当前状态以系统身份注入深度 0 供正文 API 参考。

---

## 🌟 架构总览（v2：独立更新引擎）

```
正文 API 输出: <maintext>正文</maintext> + [IMG_GEN]…[/IMG_GEN] + 【状态栏标记点】
                   │ (楼层渲染完成 → 局部正则把标记点替换为小部件 iframe)
                   ▼
小部件 iframe (每楼一个):
  ├ 数据源: 本楼消息变量 stat_data ──(无则回退解析本楼 <Status_block> 旧格式)
  ├ 更新引擎: generateRaw + custom_api(独立端点/密钥/模型) + json_schema
  │    输入 = 当前状态YAML + 最近剧情正文；输出 = 完整状态JSON → 校验/坐标夹取
  │    → 写入本楼消息变量 stat_data (每楼每swipe独立快照)
  ├ 注入引擎: injectPrompts 深度0 system = 最新状态YAML(剔除「行动选项」)
  └ 事件刷新: eventEmit('mms:status-updated') → 本楼 iframe 原地重渲染
```

### 解决的问题

| 痛点 | 解法 |
|---|---|
| 正文 API 同时输出状态栏 → 楼层慢，生图/音效插件延迟 | 正文只需输出一个 ~10 token 的标记 `【状态栏标记点】`，楼层完成大幅提前 |
| 状态栏输出指令占用正文 API 注意力 | 正文提示词不再含状态栏 schema；当前状态经深度 0 注入回喂 |
| 状态数据怕 swipe/删楼/分支 | 状态存楼层消息变量，每楼每 swipe 独立快照；旧楼层显示当时状态 |
| 手机/PC 双份 HTML 手工维护漂移 | `build_regex.mjs` 从单一 HTML 源自动生成正则 JSON |

## 🌟 主要特性

### 1. 🗺️ 战术视觉地图引擎 (Tactical Map Engine)
* 智能环境识别：根据地图名称关键字自动匹配 20+ 种 CSS/SVG 矢量底图或外部高清背景。
* 三维浮动地标：RPG 风格悬浮 Emoji 地标（呼吸灯动画），点击查看详情并可一键「前往该地」。
* 拖拽与缩放：1000x1000 网格，鼠标/触摸拖拽，滚轮/按钮缩放。

### 2. 🎭 动态立绘与头像引擎
* 高性能单次 DOM 遍历 + 差分匹配（`【立绘 名字】` 标签，含模糊回退与空格容错）。
* 立绘自动注入与 PC 灯箱预览；`PORTRAIT_MAP` / `AVATAR_MAP` / `BACKGROUND_MAP` 字典配置。

### 3. 📊 多维状态展示卡片
* 盟友/NPC/敌人自动归类着色；物品/地点/角色徽章系统（超阈值折叠）。
* PC 端双栏立绘布局；6 款主题（修仙/白天/血色/古典/黑夜/小清新）。

### 4. 🆕 独立状态更新引擎 (MMS)
* **自动更新**：最新 AI 楼层渲染时自动触发，或楼层内容变化（swipe/编辑，按消息哈希检测）时重更新。
* **手动修正**：状态栏右上角 ✏️ 按钮 → 纯文本 YAML 编辑态 → 保存写回本楼变量（保存时校验 + 错误行号提示）。
* **失败处理**：自动重试 3 次（退避），失败保留旧状态 + 红色指示器（点击重试）。
* **标记兜底**：正文 AI 忘记输出标记点时自动补写。
* **并发安全**：同一时刻仅一个更新请求；事件跨 iframe 刷新不重载 iframe、不重绘其他楼层。

## 📋 数据格式（状态栏 schema）

独立更新 AI 维护的数据结构与旧版 `<Status_block>` YAML 完全一致（见下方模板），因此：
* 旧聊天的 `<Status_block>` 楼层可直接「从本楼导入」迁移；
* 渲染引擎（地图/立绘/卡片）零改动兼容。

量化字段约定（更新 AI 会严格遵守，程序层还会做坐标 0-1000 夹取）：
* 属性：`[❤️HP:10/10][🔮MP:110/110][🛡️Armor:4][🧠SAN:59/65]`
* 物品：`[💼] [物品A] [物品Bx3]`
* 小地图地标：`"Emoji【名称】(X, Y) 描述"`（坐标 0-1000 整数）
* 人物条目：`"Emoji【姓名】[标签1] [标签2] 行为描述"`

## ⚙️ 部署与使用

### 1. 构建与导入

```bash
node build_regex.mjs
```

生成两个 SillyTavern 正则脚本（每次修改 HTML 后重新构建导入）：
* `regex-美化状态栏[独立更新].json` — **显示用**：把楼层中 `【状态栏标记点】`（或旧 `<Status_block>`）替换为小部件 iframe。
* `regex-状态栏标记清理[上下文].json` — **提示词用**：从发给 AI 的上下文剥离标记点。

导入：SillyTavern → 扩展 → 正则 → 导入脚本（建议放入**局部正则**，随角色卡生效）。旧的「美化状态栏[手机专用]」等同类脚本请禁用，避免重复替换。

### 2. 配置独立更新 AI

打开任一楼层的小部件 → ⚙️ 设置 → 「独立更新 AI」：
* API 源 / API 地址 / 密钥 / 模型；或填写酒馆代理预设名称（优先）。
* 留空地址与预设时使用当前酒馆连接的 API。
* 配置存于酒馆助手**全局变量**（跟随用户存档，PC/手机共用）。

### 3. 旧聊天迁移

打开任意有 `<Status_block>` 的楼层 → ⚙️ 设置 → 「从本楼导入」，即可把该楼状态保存为变量快照，后续楼层自动接续更新。

### 4. 正文系统提示词模板

在角色卡/预设中加入（替代旧版大段 Status_block schema 指令）：

```markdown
# 状态栏指令
把回复正文包裹在 <maintext></maintext> 中。不要输出任何状态栏、属性面板或数据块。
在回复的最末尾，单独一行输出标记：【状态栏标记点】
```

当前状态会由系统在深度 0 以系统身份注入（含全部状态数据、不含行动选项），撰写正文时必须与其保持一致。

## 🛠️ 工作原理（接口层）

| 能力 | 酒馆助手接口 |
|---|---|
| 楼层定位 | `getCurrentMessageId` / `getChatMessages` / `getLastMessageId` |
| 状态存储 | `insertOrAssignVariables` / `getVariables`（`{type:'message', message_id}`，键 `stat_data`；`$mms_meta` 存消息哈希，`$` 前缀对 AI 不可见） |
| 独立 LLM | `generateRaw({ordered_prompts, custom_api, json_schema, should_silence:true})` |
| 深度0注入 | `injectPrompts`（id `mms-status-inject`，position in_chat, depth 0, role system） |
| 跨iframe刷新 | `eventEmit` / `eventOn`（自定义事件 `mms:status-updated` / `mms:status-update-failed`） |
| 标记兜底 | `eventOn(tavern_events.MESSAGE_RECEIVED)` + `setChatMessages({refresh:'affected'})` |
| 行动发送 | `triggerSlash('/send …|/trigger')` / 父页面输入框 |

配置存储：全局变量 `$mms_config`。界面偏好（主题/显示模式/阈值等）仍存 localStorage。

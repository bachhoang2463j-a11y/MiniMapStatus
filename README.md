# MiniMapStatus (故事情节与战术地图状态栏)

`MiniMapStatus` 是一个专为 **SillyTavern (酒馆)** 设计的高颜值、交互式状态栏与战术地图小部件，运行于 **酒馆助手 (TavernHelper / JS-Slash-Runner)** 的 iframe 渲染环境。

它通过独立 AI（与正文 API 分离）维护一份完整的跑团状态数据（角色属性、物品、小地图坐标、人物/据点、行动选项），渲染为包含**战术视觉地图**、**角色多维状态卡片**、**动态立绘**、**物品行囊**的交互式面板，并把当前状态以系统身份注入深度 0 供正文 API 参考。

---

## 🌟 架构总览（v3：独立更新引擎 + 固定角色名册 + 校验命令协议）

```
正文 API 输出: <maintext>正文</maintext> + [IMG_GEN]…[/IMG_GEN] + 【状态栏标记点】
                   │ (楼层渲染完成 → 局部正则把标记点替换为小部件 iframe)
                   ▼
小部件 iframe (每楼一个):
  ├ 数据源: 本楼消息变量 stat_data ──(无则回退解析本楼 <Status_block> 旧格式→自动规范化)
  ├ 更新引擎: generateRaw + custom_api(独立端点/密钥/模型)（不传 json_schema，靠提示词契约 + 返回后解析）
  │    输入 = 当前状态YAML + 固定成员名册 + 最近剧情正文
  │    输出 = 自由字段全量JSON + 校验字段命令 → 合并引擎(命令应用+名册合并+模块兜底)
  │    → 写入本楼消息变量 stat_data (每楼每swipe独立快照；写回固定的 swipe，不切用户当前页)
  │    → 同楼重算时与"上次 AI 结果"对账，保留手动编辑与结算直连写入的字段
  ├ 注入引擎: 角色卡主世界书的「MMS-状态栏数据」条目（at_depth 深度0 system）=
  │    最新状态YAML(剔除「行动选项」，含全部固定角色)；换聊天时由宿主级守卫清理
  └ 事件刷新: eventEmit('mms:status-updated') → 本楼 iframe 原地重渲染
```

### 解决的问题

| 痛点 | 解法 |
|---|---|
| 正文 API 同时输出状态栏 → 楼层慢，生图/音效插件延迟 | 正文只需输出一个 ~10 token 的标记 `【状态栏标记点】`，楼层完成大幅提前 |
| 状态栏输出指令占用正文 API 注意力 | 正文提示词不再含状态栏 schema；当前状态经深度 0 注入回喂 |
| 状态数据怕 swipe/删楼/分支 | 状态存楼层消息变量，每楼每 swipe 独立快照；旧楼层显示当时状态 |
| 多份 HTML 手工维护漂移 | `build_regex.mjs` 从各自 HTML 源生成对应正则 JSON（完整版/公开版各自一份） |
| 更新 AI 全量改写属性/物品 → 幻觉风险 | **校验字段命令协议**：量化数据只能以 `[HP-2]`/`[+绷带x2]` 式命令变更，未提及=结构性保持 |
| 团队角色被正文 AI 遗忘（被迫塞进盟友列表） | **固定角色名册**：常驻角色列表+属性，漏输出时保留数值+占位标注 |
| 「一切伪装成用户列表」的遗留结构混乱 | **模块化结构**：小地图/角色列表/人物/据点/行动选项各自独立，旧结构自动规范化转换 |

## 🆕 v3 核心机制

### 固定角色名册（设置 → 固定角色）
* **添加角色**：自由规定姓名、数值校验属性键与初始值（`❤️HP:18/18` 或修仙风的 `气血:120`）、立绘标签，以及一套**完全自定义的字段列表**——每个字段可单独勾选「校验」（走命令协议，适合武器/物品/弹药/消耗/道具等清单字段）或「自由」（每轮全量输出，适合穿着/内心等）。新角色默认预填 武器/物品（校验）+ 穿着/内心（自由），可任意增删改名。
* 名册角色**永远显示角色卡**（现有「角色状态详情」标签页，样式不变），即使本轮剧情未提及。
* 漏输出的双档占位：名称出现在本轮正文 → 「在场·本轮未详」；完全未出现 → 「本轮未提及」（两文案均可自定义）。
* 占位有**连续缺席阈值**（名册里可配，默认 3 轮）：连续漏输出不超过阈值时保留上轮自由字段（穿着/内心等原样沿用），超过阈值才换成占位文案。整份角色列表被 AI 省略时不计缺席轮数。
* 副作用：名册角色合并进状态后随深度 0 注入 → **正文 API 不会再忘记他们**。
* 存储：聊天变量 `$mms_roster`（随聊天导出）。删除角色只影响后续显示。

### 校验字段命令协议
适用于角色名册中标注「校验」的字段（默认属性/武器/物品，可加弹药/消耗/道具等）与各固定模块的现金/清单字段：

| 命令 | 含义 | 示例效果 |
|---|---|---|
| `[键-N]` / `[键+N]` | 减/增（cur/max 型只作用当前值并夹取） | `[HP-3]`：`[❤️HP:10/10]`→`[❤️HP:7/10]` |
| `[键:值]` | 设值（cur/max 型：当前值夹取到 `[0, 上限]`，**上限锁定**不可被 AI 改写） | `[SAN:55]`；`[HP:99/12]`→`[❤️HP:12/12]`、`[HP:8/99]`→`[❤️HP:8/12]` |
| `[名称+N]` | 获得物品（与属性语法同构；旧式 `[+名称]` / `[+名称xN]` 仍兼容） | `[绷带+2]` |
| `[名称-N]` | 消耗物品（计数条目**归零保留为 0** 并在渲染层标红；无数量物品消耗即移除） | `[.45子弹-40]` |
| `[名称:N]` | 设为数量 | `[子弹:10]` |
| `[团队现金±N]` | 现金增减（保留货币后缀） | `[团队现金-12.80]` → `4754.40美元` |
| 不输出该字段 | **结构性保持不变**（不是提示词请求，是程序保证） | |
| 完整值（带emoji键名） | 新角色/新属性全量替换 | `[❤️HP:12/12][🛡️Armor:2]` |
| 原样重述整份清单 | **判定为全量重述，不累加**（防止 AI 忘记增量协议时静默翻倍） | `[.45子弹x30][绷带]` 重述后不变 |
| 无有效条目（`[]`/纯文本/只有 `[💼]` 装饰段） | **保留原值并告警**，不允许覆盖已有数据（无历史值时才原样写入） | `"物品": "无"` → 清单不变 |

* 名称模糊匹配（去emoji/标点/空格），`[旧式绷带-1]` 能命中清单里的「旧式绷带x2」。
* **括号备注 = 随身放置位置**：`[柯尔特M1911(夹克内侧)]`。换位置时重述该条目改写括号即可（`[柯尔特M1911(腰后)]`），程序按"剥掉备注的主名"识别为同一件、只改备注不新增条目；不带备注的命令（`[柯尔特M1911-1]`）不会抹掉已有备注。同一清单里已有两把同型枪时，第三个不同备注按新条目入列（避免误合并）。
* 数量两种格式等价：`[绷带x2]` 与 `[绷带：2]`（rpgcombat 风格中文冒号计数，如 `[.45子弹：700]`），命令增减后按原格式回写。
* 自由字段（日期/地点/小地图/行动选项/名册中标注自由的字段/自定义模块）每轮全量输出；**「人物」不是自由字段**——它按姓名增量合并：同名=更新描述（可跨分类移动）、新名=登记、未提及=保留、输出 `"【名字】[移除]"` 才删除；名字是职业/身份词的临时角色（侍者/混混/邪教徒等）不进「人物」，只在小地图出现（可用「人物过滤词」补充自建词表）。

### 模块化状态结构（开放式）
```yaml
状态栏:
  日期和时间 / 地点:        # 自由·全量
  小地图: {场景键: [地标]}   # 自由·全量，坐标10~90，场景键取自「地图管理」标签池
  角色列表:                 # 固定名册在前；属性与校验字段=命令，自由字段=全量
  人物: {盟友/NPC/敌人}      # 按姓名增量合并（非全量）
  据点: {名称,现金,武器,防御,杂物}   # 固定模块：现金/清单=命令
  载具: {名称,武器,弹药,杂物}        # ★固定模块可多个共存（据点+载具同时常驻）
  行动选项: {名字,选项}      # 自由·全量
  线索: {...}               # ★自定义模块：全量·透传，AI省略则保留上次
```
* **固定自定义模块（多个共存）**：据点、载具、情报站等任意常驻模块，各自配置模块名/名称/现金（留空不输出）/清单字段；启用后常驻显示、缺失字段用基线补齐，AI 漏输出不消失。
* **实时配置**：名册与固定模块表单显示的是当前状态栏的**实时值**（非初始基线），修改后直接写入当前楼层状态并即时刷新，无需进 YAML 编辑器；每个模块卡片可折叠（收起只留启用/模块名/删除）。
* **状态快照**：主视图右上角 📷 按钮——随时保存当前状态为回退点（默认保留 3 份，与修改历史独立），可一键恢复到当前楼层。
* **键名容错**：状态顶层键带 emoji 前缀（如「🏟️据点」「🚙载具」）时与名册纯名模块自动归一匹配，不会重复建模块。
* **旧结构完全兼容**：`用户列表`（含"团队行动"错位条目）自动规范化转换；总览拆出名称/现金；据点/载具等多模块条目各自独立成模块（不再互相合并覆盖）；未知条目转自定义模块。
* **自定义模块兜底**：线索/情报等累积型卡片 AI 漏更新时保留上次内容；未注册为固定模块的据点也能透传保留。
* **一键导入**：从本楼状态检测到的新角色与模块弹勾选框逐项导入（不再全量导入）；角色字段按「值含 [ ] 括号 → 校验、纯文本 → 自由」自动分类并带入初值。
* 自定义更新提示词替换的是**系统提示词文本**（「设置 → 提示词预设」，可自定义卡片类型协议）；程序侧的 JSON 解析与校验字段命令协议是固定的，不做任意格式解释。返回内容仍需是含内置模块键的 JSON 对象。

## 🌟 主要特性

### 1. 🗺️ 战术视觉地图引擎 (Tactical Map Engine)
* 智能环境识别：根据地图名称关键字自动匹配 30+ 种内置 CSS/SVG 矢量底图或外部高清背景（可在「图片管理」增删底图，标签池自动同步）。
* 三维浮动地标：RPG 风格悬浮 Emoji 地标（呼吸灯动画），点击查看详情并可一键「前往该地」。
* 拖拽与缩放：1000x1000 网格，鼠标/触摸拖拽，滚轮/按钮缩放。

### 2. 🎭 动态立绘与头像引擎
* 高性能单次 DOM 遍历 + 差分匹配（`【立绘 名字】` 标签，含模糊回退与空格容错）。
* 立绘自动注入与 PC 灯箱预览；`PORTRAIT_MAP` / `AVATAR_MAP` / `BACKGROUND_MAP` 字典配置。
* **拆分立绘切换（玩家手动，零 LLM 开销）**：点击角色卡立绘打开灯箱后，底部出现该角色的全部立绘变体条（按角色名匹配 `PORTRAIT_MAP` 键，如 弗兰克 ↔ 弗兰克脱衣），点击即切换——灯箱大图与卡片立绘即时更新，选择写入聊天变量 `$mms_portrait_choice` 持久化，重渲染/换楼层后沿用，随时可再点换回。
* **生效头像表对外共享**：经酒馆助手跨 iframe 接口 `initializeGlobal('MMSImages')` 共享（`avatarMap` 活引用 + `resolveAvatar(名称/网址)`），商店等外部前端可直读权威头像（含名册覆盖与图片管理改动），见 2.3 图片管理。

### 3. 📊 多维状态展示卡片
* 盟友/NPC/敌人自动归类着色；物品/地点/角色徽章系统（按**每行字符数**折叠——设置面板「徽章折叠字符数」可调，默认 40：徽章文本按显示顺序累计，超过阈值的部分折叠为"+N"，点开可展开/收起；按自己的字体与屏宽自行校准）。
* PC 端双栏立绘布局；6 款主题（修仙/白天/血色/古典/黑夜/小清新）。

### 4. 🆕 独立状态更新引擎 (MMS)
* **自动更新**：新 AI 楼层生成完毕时自动触发（唯一触发点）；楼层内容变化（swipe/编辑，按消息哈希检测）仅亮红点提醒，需手动「立即更新」，不额外消耗 token。
* **手动修正**：状态栏右上角 ✏️ 按钮 → 纯文本 YAML 编辑态 → 保存写回本楼变量（保存时校验 + 错误行号提示）。
* **失败处理**：自动重试 3 次（退避），失败保留旧状态 + 红色指示器（点击重试）。
* **标记兜底**：正文 AI 忘记输出标记点时自动补写。
* **并发安全**：boot 自触发、新楼代理、手动按钮全部走同一入口，跨楼层实例共享进行中台账——同一楼层同时只有一个请求，不同楼层串行执行；事件跨 iframe 刷新不重载 iframe、不重绘其他楼层。

## 📋 数据格式（状态栏 schema，v3 模块化结构）

程序内部维护**模块化结构**；旧版 `用户列表` 格式在所有读取入口自动规范化转换（渲染/更新/导入/编辑全兼容）：
* 旧聊天的 `<Status_block>` 楼层可直接「从本楼导入」或直接等下一次自动更新（自动转换）；
* 渲染引擎（地图/立绘/卡片）复用原有分发逻辑，样式不变。

量化字段约定（程序层夹取：坐标 10~90）：
* 属性：`[❤️HP:10/10][🔮MP:110/110][🛡️Armor:4][🧠SAN:59/65]`（键名可自定义，如修仙风 `气血`）
* 物品：`[💼] [物品A] [物品Bx3]`
* 小地图地标：`"Emoji【名称】(X, Y) 描述"`（坐标 10~90 整数，程序会夹取）。场景键取自「地图管理」页签的标签池；**默认分配前 18 个内置 SVG 场景给小地图**，其余场景与自定义底图可按需分配到小地图或大地图（并非只支持 18 个场景）
* 人物条目：`"Emoji【姓名】[标签1] [标签2] 行为描述"`

## ⚙️ 部署与使用

### 1. 构建与导入（标准交付流程）

> **关键事实**：酒馆渲染的 iframe 用的是**正则 JSON 里内嵌的 HTML 副本**（构建时拷贝进去的），
> 直接改磁盘上的 `MiniMapStatus.html` 不会生效——必须重新构建 JSON 并导入酒馆。

**开发侧（每次代码改动后）：**

本项目有**两份并列的完整版源码**，各自产出独立正则、互不覆盖：

| 源码 | 产物 | 说明 |
|---|---|---|
| `MiniMapStatus.html` | `regex-美化状态栏[独立更新].json` + `regex-状态栏标记清理[上下文].json` | 非公开完整版（功能齐全） |
| `MiniMapStatus-公开版.html` | `regex-美化状态栏[公开版].json` | 公开版：内置图片表精简为公开角色，其余逻辑与非公开版一致 |

两者是**人工维护的两份文件**（公开版不会随默认构建自动同步）；改动引擎逻辑时需要**两边都改**，`test-runtime.mjs` 会用同一套用例跑两份源码。

```bash
# 1. 修改源码（非公开 MiniMapStatus.html；公开版 MiniMapStatus-公开版.html）
node build_tailwind.mjs                 # 2. 若改了 class 工具类/主题色：重建内联 Tailwind 产物 CSS
node build_regex.mjs                    # 3. 重建非公开版正则 JSON（内嵌最新 HTML 全文，自动压缩）
```

### 2. 配置独立更新 AI

打开任一楼层的小部件 → ⚙️ 设置 → 「独立更新 AI」：
* API 源 / API 地址 / 密钥 / 模型；或填写酒馆代理预设名称（优先）。
* 留空地址与预设时使用当前酒馆连接的 API。
* **剧情回溯楼层数**（默认 2）：`<最新剧情>` 恒为「本轮用户指令 + 本楼 AI 正文」成对发送（用户指令里明示的数值变化，即使正文没转述也能计入）；设为 **≥3** 时才追加 `<前情提要>`，条数为 N−2 层。
* **自定义更新提示词**：替换内置**系统提示词文本**（可自定义卡片类型协议；留空用默认，「恢复默认提示词」一键清除）。程序侧的 JSON 解析与校验字段命令协议固定，不做任意格式解释。
* 配置存于酒馆助手**全局变量**（跟随用户存档，PC/手机共用）。

### 2.1 更新 AI 收到的内容（与主 API 完全无关）

`generateRaw` 只发送下面两条消息，**不加载**酒馆预设、世界书、角色卡、用户人设、酒馆正则、完整聊天楼层：
* **[system]** 自定义提示词（或内置默认的「跑团状态栏数据管理员」提示词：输出契约 + 命令协议 + 自由字段生成指引 + 目标结构参照，按名册/模块/地图配置动态拼装）
* **[user]** `<当前状态>` 最近一份状态 YAML（从本楼往前找，最多回溯 50 楼） + `<前情提要>` N−2 层更早楼层（仅 N≥3 时） + `<最新剧情>` 用户指令与本楼 AI 正文成对（已剥离 `[IMG_GEN]` 图片指令与标记点） + `<成员人设>` 仅配了人设的成员（置于最新剧情之后） + 结尾输出指令

### 2.2 固定角色名册（设置 → 固定角色）

* **添加角色**：姓名（可带emoji）、立绘标签（可选）、数值校验属性（每行 `键:初始值`，键名自由——HP 还是气血由你决定）、字段列表（每行 `字段名:初始值 + 校验/自由开关`，默认预填 武器/物品（校验）与 穿着/内心（自由），可加弹药/消耗/道具等任意清单字段）。
* 添加后立即合并进当前楼层状态，新角色当场出现在角色标签页。
* 两个占位文案可自定义（默认「本轮未提及」/「在场·本轮未详」）。

### 2.3 图片管理（设置 → 图片管理）

管理内置三张图片表：**立绘**（PORTRAIT_MAP，按角色名含状态变体匹配）、**大地图底图**（BACKGROUND_MAP，按地图名匹配）、**小头像**（AVATAR_MAP，按角色名匹配小地图标记）。

* **查看**：缩略图 + 名称 + 链接，按分类切换、支持搜索。
* **增删改**：编辑即时生效（缩略图、地图底图、名册头像下拉同步刷新），并**自动保存在本设备**（localStorage，防抖落盘）；底图增删后「地图管理」页签的标签池自动同步。
* **保存到源码**：把三张表写回**正则 `replace_string` 里的源码标记块**（`MMS_IMAGE_DATA_START/END` 之间）。数据真正存在源码中——随正则导出即迁移，全局生效，不写聊天记录。保存后酒馆会自动重载页面加载新配置。
  * 定位规则：按**本版本自身的正则身份**（固定 UUID 优先、脚本名次之）在全局与角色局部范围内查找，且只认带图片标记块的条目；身份无法唯一确定时会提示并**拒绝写入**，不会误改另一版本的正则。
* **本机改动 vs 源码**：顶部徽标显示「未写回源码 N 项」（相对于源码内置表的差异）。增删改**已自动落盘本机**，刷新页面不会丢失；「保存到源码」是把它固化进正则副本以便跨设备迁移。
* **导出 / 导入 / 复制配置**：JSON 备份，或复制标记块代码粘贴回本地源码。
* **对外共享（供商店等外部前端直读）**：生效头像表（内置表 + 名册覆盖 + 图片管理改动）经酒馆助手跨 iframe 接口 `initializeGlobal('MMSImages')` 共享，共享的是运行时表活引用，名册覆盖后即时可见、无需重新注册；同时防抖落盘只读导出键（非公开版 `mms_avatar_export_v1`、公开版 `mms_avatar_export_public_v1`；只含 avatar，不夹带立绘表）。需酒馆助手 3.6.2+；旧版环境静默跳过，MMS 自身行为不变。
* **本机快照按版本隔离**：非公开版用 `mms_img_data_llm_v1`（与「手机专用LLM地图」版互通），公开版用 `mms_img_data_public_v1`。两版共用同一酒馆源时互不覆盖；需要迁移请用导出/导入。

> **与本地开发的覆盖关系**：浏览器端「保存到源码」改的是酒馆里的正则副本；本地源码文件不会自动同步。若之后在本地改代码并重新 `node build_regex.mjs` 导入，**会覆盖**浏览器端保存的图片配置——先在小部件里点「复制配置」，把标记块粘贴回本地源码的 `MMS_IMAGE_DATA_START/END` 之间再构建，即可两全。本机快照（localStorage）不受重新导入影响。
>
> 名册角色自带的头像只在运行时覆盖同名小头像（当轮聊天生效，不写入源码）；无酒馆助手正则 API 的环境（如本地直接打开 HTML 预览）保存会提示改用导出/复制。
> 设置页签超过 5 个后页签栏可横向滚动：PC 按住拖动，移动端原生滑动，两端有渐隐提示。

### 3. 旧聊天迁移

### 4. 正文系统提示词（**由用户自行维护，本项目不内置也不改动**）

> 本项目的正则与源码**不包含**正文提示词，也不在运行时改写你的角色卡/预设。以下只是与当前默认开关对应的**参考写法**，请自行复制到你自己的角色卡或预设里。

当前状态会由系统在深度 0 以系统身份注入（含全部状态数据、不含行动选项），撰写正文时必须与其保持一致。按「设置 → 行动选项由正文 AI 生成」开关选一种：

**A. 默认开启（行动选项由正文 AI 生成）** —— 用 `Status_block` 挂载，不要再额外输出标记点，避免两个挂载点并存：

```markdown
# 正文与行动选项
依据系统提供的当前状态继续剧情，把正文包裹在 <maintext></maintext> 中。
正文之后输出一个 <Status_block>，其中只写本轮的行动选项。属性、物品、现金、人物登记和地图交由独立状态更新器维护。
提供四条有具体执行角色的行动：检定探索、直接推进、谨慎观察、救助交涉；从 1 开始编号。

输出结构示例：
<maintext>索恩停在仓库门外，威廉发现门缝里透出灯光。</maintext>
<Status_block>
状态栏:
  行动选项:
    名字: "团队行动"
    选项:
      - "1. 🎲【侦查检定】索恩检查门锁附近的痕迹"
      - "2. 🎯 威廉敲门询问仓库内的人"
      - "3. ⌛ 索恩隐蔽观察侧窗的动静"
      - "4. 🦢 威廉询问屋内是否有人需要帮助"
</Status_block>
```

**B. 关闭该开关（行动选项由独立更新 AI 生成）**：

```markdown
# 正文输出
依据系统提供的当前状态继续剧情，把正文包裹在 <maintext></maintext> 中。
状态数据与行动选项由独立状态更新器维护。回复最末单独一行输出：【状态栏标记点】。

输出结构示例：
<maintext>索恩停在仓库门外，威廉发现门缝里透出灯光。</maintext>
【状态栏标记点】
```

两种写法都只产生**一个**状态栏挂载点；若同时输出标记点与 `Status_block`，显示正则只会替换其中一个（标记点让位给 `Status_block` 分支）。

## 🛠️ 工作原理（接口层）

| 能力 | 酒馆助手接口 |
|---|---|
| 楼层定位 | `getCurrentMessageId` / `getChatMessages`（含 `include_swipes` 取各 swipe 槽）/ `getLastMessageId` |
| 状态存储 | `insertOrAssignVariables` / `replaceVariables` / `getVariables` / `setChatMessages`（`{type:'message', message_id}`，键 `stat_data`；`$mms_meta` 存消息哈希与 `aiState` 比对基线，`$` 前缀对 AI 不可见） |
| 独立 LLM | `generateRaw({ordered_prompts, custom_api, should_silence:true})`（不传 `json_schema`） |
| 深度0注入 | 角色卡主世界书条目「MMS-状态栏数据」（`at_depth`、role system、depth 0、order 10；由脚本创建/更新，用户可在世界书编辑器自由调整位置） |
| 跨iframe刷新 | `eventEmit` / `eventOn`（自定义事件 `mms:status-updated` / `mms:status-update-failed`） |
| 标记兜底 | `eventOn(tavern_events.MESSAGE_RECEIVED)` + `setChatMessages({refresh:'affected'})` |
| 行动发送 | `triggerSlash('/send …|/trigger')` / 父页面输入框 |

配置存储：全局变量 `$mms_config`。界面偏好（主题/显示模式/阈值等）仍存 localStorage。
